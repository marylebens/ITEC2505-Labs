Module 12 Lab: Razor Forms and Validation

Let's build a signup form that checks what people type before it accepts it.

Introduction

Real web apps never trust what people type into a form. Someone leaves a field blank, mistypes an email address, or asks for negative tickets. In this lab you'll build a campus event signup form using the Razor framework's built in tools for handling exactly that: model binding, validation attributes, tag helpers, and redirecting to a confirmation page once everything checks out.

Background: What Happens When You Submit a Form

Here's the full trip, start to finish, and it's worth reading twice because it's how nearly every website works:

  1. Your browser asks the web server for the Signup page by sending a request to its URL. The server runs the page's OnGet method and sends back HTML, which your browser displays as a form.
  2. You fill in the form and click submit. Your browser sends a second request to the same URL, but this time it's a POST request carrying everything you typed.
  3. The server runs the page's OnPost method. Model binding automatically copies each value from the request into the matching C# property, so you never dig through the raw request yourself.
  4. Razor checks every value against the validation attributes on those properties, like [Required] or [Range]. The result is stored in ModelState.IsValid.
  5. If something is wrong, the server sends the form back with error messages. If everything is fine, the server redirects your browser to a new URL, the Confirmation page, so the data isn't accidentally submitted twice if you refresh.

A tag helper is a special attribute like asp-for that Razor turns into regular HTML before sending the page to your browser. You'll use asp-for to connect an input box to a C# property, and asp-validation-for to show that property's error message.

Step 2: Look at the Confirmation Page

Open Pages/Confirmation.cshtml.cs. Notice the three properties each have [BindProperty(SupportsGet = true)]. That tells Razor to fill them in from the URL's query string, the part after the question mark, when the page loads. That's how the Signup page will pass the person's info to this page.

Then open Pages/Confirmation.cshtml and notice how it displays those properties with @Model.FullName, @Model.Email, and @Model.TicketCount.

Step 3: Add Properties with Validation Rules

Open Pages/Signup.cshtml.cs and replace the first TODO comment with these three properties:

[BindProperty]
[Required(ErrorMessage = "Please enter your full name.")]
public string FullName { get; set; } = string.Empty;

[BindProperty]
[Required(ErrorMessage = "Please enter your email address.")]
[EmailAddress(ErrorMessage = "That doesn't look like a valid email address.")]
public string Email { get; set; } = string.Empty;

[BindProperty]
[Range(1, 5, ErrorMessage = "You can reserve between 1 and 5 tickets.")]
public int TicketCount { get; set; }

What each piece does: [BindProperty] tells Razor to fill the property from the submitted form. [Required] rejects an empty value. [EmailAddress] rejects text that isn't shaped like an email. [Range] rejects numbers outside the limits you set. The text in ErrorMessage is exactly what the visitor will see.

Step 4: Check the Rules and Redirect

Still in Signup.cshtml.cs, replace the TODO comment inside OnPost with this code:

if (!ModelState.IsValid)
{
    // Something broke a validation rule, so show the form again.
    // The error messages appear automatically.
    return Page();
}

// Everything checked out, so send the browser to the Confirmation
// page and pass the data along in the URL.
return RedirectToPage("Confirmation", new { FullName, Email, TicketCount });

You can delete the leftover return Page(); line at the bottom of OnPost, since both paths now return above it.

Step 5: Build the Form

Open Pages/Signup.cshtml and replace the placeholder paragraph with this form:

<form method="post">
    <div class="mb-3">
        <label asp-for="FullName" class="form-label"></label>
        <input asp-for="FullName" class="form-control" />
        <span asp-validation-for="FullName" class="text-danger"></span>
    </div>

    <div class="mb-3">
        <label asp-for="Email" class="form-label"></label>
        <input asp-for="Email" class="form-control" />
        <span asp-validation-for="Email" class="text-danger"></span>
    </div>

    <div class="mb-3">
        <label asp-for="TicketCount" class="form-label"></label>
        <input asp-for="TicketCount" class="form-control" />
        <span asp-validation-for="TicketCount" class="text-danger"></span>
    </div>

    <button type="submit" class="btn btn-primary">Reserve My Spot</button>
</form>

Each asp-for connects a label and an input to a C# property. Each asp-validation-for is an empty span that Razor fills in with that property's error message when validation fails.

Before You Run It: Predict the Output

What do you expect to see if you click Reserve My Spot with every box empty? What about with a valid name and email but a TicketCount of 9? Write down both predictions before running the app in Step 6.

Step 6: Run and Test

  1. In the terminal, type dotnet run and press Enter.
  2. Open the PORTS tab, hover over the forwarded address, and click the globe icon to open your app. Click Sign Up in the nav bar.
  3. Click Reserve My Spot with everything empty, then with a bad email, then with 9 tickets, and compare each result to your predictions from Step 5.
  4. Now fill the form in correctly and submit it. Look at the address bar on the Confirmation page. Your name, email, and ticket count are right there in the URL after the question mark. That's the query string, and it's how the Signup page handed your data to the Confirmation page.
  5. When you're done testing, go back to the terminal and press Ctrl+C to stop the server.

Part 2: At Home

You'll add two new fields with your own validation rules, using the exact same skills from Part 1.

In Part 1 you typed validation rules that were already written out for you. Now you'll write your own, for two new fields, and carry them all the way through to the Confirmation page. This is required, not optional, since writing the rules yourself is what actually builds the skill.

Step 8: Reopen Your Codespace

Go to GitHub's home page, sign in, and reopen your existing Codespace, same as Step 1.

Step 9: Write a Phone Number Field

In Signup.cshtml.cs, following the same pattern as the Email property from Step 3, add a new property called Phone. It should be [BindProperty], [Required] with your own friendly error message, and use the [Phone] attribute, which rejects text that isn't shaped like a phone number, also with your own error message.

In Signup.cshtml, following the same pattern as the Email block in Step 5, add a matching label, input, and validation span for Phone.

Step 10: Write a Special Requests Field

In Signup.cshtml.cs, add a second new property called SpecialRequests. This one is optional, so don't use [Required], but do limit its length with [StringLength(100, ErrorMessage = "...")], writing your own error message that tells the visitor the 100 character limit.

In Signup.cshtml, add a matching label, input, and validation span for SpecialRequests.

Step 11: Carry Both Fields to the Confirmation Page

Three small edits connect everything:

  1. In the RedirectToPage line in Signup.cshtml.cs, add Phone and SpecialRequests to the list of values inside the curly braces, so they get passed along in the URL.
  2. In Confirmation.cshtml.cs, following the same pattern as FullName and Email, add matching Phone and SpecialRequests properties with [BindProperty(SupportsGet = true)].
  3. In Confirmation.cshtml, add two paragraphs that display @Model.Phone and @Model.SpecialRequests, so the visitor sees them echoed back.
