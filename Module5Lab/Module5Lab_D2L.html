Module 5 Lab: Object-Oriented Gaming

Let's build your first class, then teach a second class to inherit from it.

Introduction

Today you'll learn how to create your own class, and how to use inheritance to build a second class that inherits characteristics from the first. Being able to create your own classes is a big deal in programming. A class works like a blueprint or template for what any object of a specific kind needs to keep track of and be able to do.

We'll build a simple Player class, the kind of thing you might use to represent a player in a game, and by the end you'll have a second class, SuperPlayer, that inherits everything Player can do and adds something extra.

Step 2: Add Instance Variables

The first real step of building a class is giving it variables to hold its own data. One of the key traits of an object is that it keeps track of its own data, stored as variables that belong to the object. These are called attributes. We'll make each attribute private, meaning it can only be reached from inside the class. Code outside the class doesn't even know it exists. Keeping data private to the class is the OOP principle of encapsulation.

We're going to track the player's name, lives left, and current score. Open Player.cs and replace the first TODO comment with these three attributes:

private string name;
private int score;
private int livesLeft;

Step 3: Add Constructors

Now that we've got instance variables, let's add constructors. A constructor is a special method that creates a new instance of a Player object when it's called. Say a new player named Abdi logs into the game: our code calls the constructor to create a new Player object and assigns the name variable the value "Abdi". Constructors are public so code outside the class can call them to make a new Player object.

This class needs three constructors: one with no parameters, one that takes just a name, and one that takes both a name and a number of lives. Replace the second TODO comment with:

public Player()
{
}

public Player(string name)
{
    this.name = name;
}

public Player(string name, int startingLives)
{
    this.name = name;
    livesLeft = startingLives;
}

Step 4: Add Methods

Now let's add methods. A method is a block of code that defines an action an object can perform. A method's signature has an access level (public, private, and so on), a return type, a name, and any parameters it takes.

We'll add methods to get the player's name and score, add points to the score, "kill" the player (losing a life), and check how many lives are left. Replace the third TODO comment with:

public int GetScore()
{
    return score;
}

public void AddPoints(int totalPoints)
{
    score += totalPoints;
}

public void Kill()
{
    // We make sure they can't get negative lives.
    if (livesLeft > 0)
    {
        livesLeft--;
    }
}

public int GetLivesLeft()
{
    return livesLeft;
}

Step 5: Test Your Player Class

Open Program.cs and replace the TODO comment with this code:

// Create a new player with one life and add points to the player's score
Player player = new Player("Frankenstein", 1);
player.AddPoints(100);

// Display the player's score
Console.WriteLine("Welcome to the game! Your score is: " + player.GetScore() +
    " You have " + player.GetLivesLeft() + " lives left!");

// Kill off the player's character
player.Kill();

// Let the player know their character was killed
Console.WriteLine("An orc attacks you. Sorry, you were killed. You have "
    + player.GetLivesLeft() + " lives left!");

Before you run it, predict the output.

Frankenstein starts with 1 life and 0 points, then gains 100 points, then gets killed. What will the two Console.WriteLine lines print? Write down your prediction before moving on to Step 6.

Part 2: At Home

You'll build a whole new class yourself this time, using the exact same skills from Part 1.

Background: Inheritance in C#

Inheritance lets you create a new class that automatically gets the properties and methods of an existing class, then adds its own extras on top. The existing class is called the base class, and the new one is called the derived class. You mark a derived class with a colon and the base class name: class SuperPlayer : Player

A SuperPlayer built this way already has GetScore, AddPoints, Kill, and GetLivesLeft, without you writing any of that code again. You only need to write what's new.

Step 8: Reopen Your Codespace and Create SuperPlayer.cs

  1. Reopen your Codespace and open the Module5Lab folder, same as Step 1.
  2. In the Explorer, right click on the Module5Lab project folder and choose New File. Name it SuperPlayer.cs.
  3. This file is empty, unlike Player.cs. You're writing this one entirely yourself. Start it off with:
    namespace Module5Lab;

Step 9: Write the SuperPlayer Class

Below the namespace line, declare the class, following the same colon pattern from the Background section above, so SuperPlayer inherits from Player:

internal class SuperPlayer : Player

Inside the class body, write a public method called Fly that takes no parameters and returns nothing, following the same method pattern from Step 4, that prints "SuperPlayer is flying!" to the console with Console.WriteLine.

Then add a second method of your own choosing, something a SuperPlayer can do that a regular Player can't, like Teleport or ShootFireballs. It should also print a message describing what happened.

Step 10: Test Your SuperPlayer Class

Open Program.cs and add this below your existing Player code:

// Create a super player
SuperPlayer superPlayer = new SuperPlayer();
superPlayer.AddPoints(200);
superPlayer.Fly(); // Demonstrate the additional ability
Console.WriteLine($"SuperPlayer score: {superPlayer.GetScore()}, Lives left: {superPlayer.GetLivesLeft()}");

Then call your second SuperPlayer method too, the one you invented in Step 9, so it actually runs and prints its message.

Before You Run It: Predict the Output

superPlayer starts with a fresh no-parameter constructor, so it starts at 0 lives, then gains 200 points, then flies, then does whatever your second ability does. What will AddPoints, Fly, your second method, and the final Console.WriteLine each print? Write down your prediction before running it in Step 11.

Step 11: Run and Check Your Prediction

  1. In the terminal, type dotnet run and press Enter.
  2. Confirm you see both the Player output from Part 1 and the new SuperPlayer output, including your invented ability's message.
  3. Notice that SuperPlayer could call GetScore and GetLivesLeft even though you never wrote those methods in SuperPlayer.cs. That's inheritance at work, those methods came along for free from Player.
