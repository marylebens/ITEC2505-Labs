Module 7 Lab: SQL Statements

Let's build a real database, then learn to talk to it.

Introduction

This is a jam packed lab. We'll build and populate a database called Northwind Traders, then write SQL SELECT queries together to pull data out of it. SELECT queries are statements used to retrieve data from a database, and they're the single most common thing you'll write as a developer working with data.

Background: What Is Forking a Repo?

What is a fork? A fork is your own copy of someone else's repository. Forking lets you freely experiment with changes without touching the original project, like a fork in the road, where the original repo keeps going one direction and your copy goes its own way.

Why are we forking a different repo instead of using our usual one? Today's repo contains a Docker container your instructor set up. Docker is a popular platform for creating and running containers, which are lightweight, isolated environments that package an application along with everything it needs to run.

What's in this container? It's already set up with Microsoft SQL Server and .NET, so you don't need to install and configure those tools yourself. It also contains the SQL script we'll use to build the Northwind database.

Background: The Northwind Database

Northwind Traders is a fictional company that imports and exports specialty foods, and Microsoft built this sample database to teach SQL. It manages orders, products, customers, suppliers, and more, which makes it a great playground for practicing real queries.

Northwind Database Entity-Relationship Diagram (ERD)

An ERD, or Entity Relationship Diagram, is a visual map showing how the tables in a database relate to each other. Entities are the tables, attributes are the columns, and relationships show how tables connect, usually through a primary key in one table matching a foreign key in another. For example, SupplierID is the primary key in Suppliers and a foreign key in Products, which is why those two tables are related.

Pro tip: keep this ERD handy while writing SQL. Table and column names need to match the database exactly, so use the ERD as your spelling reference.

Step 3: Build the Northwind Database

  1. Open the Explorer with Ctrl+Shift+E, and find the file 01-CreateDatabase.sql.
  2. Double click it to open it. This file contains the SQL that creates and populates the Northwind database. Scroll through it to see the table and data setup, then leave it as is.
  3. Open a terminal with Ctrl+Shift+backtick, then run this command:
    sqlcmd -S localhost,1433 -U sa -P P@ssw0rd -d master -i 01-CreateDatabase.sql
  4. If it works, you'll see one line: "Changed database context to 'Northwind'." If it doesn't, check for a typo and try again.

What that command does

  • sqlcmd connects to SQL Server.
  • -S localhost,1433 is the server name and port.
  • -U sa is the username, sa stands for server administrator.
  • -P P@ssw0rd is the password for that account.
  • -d master connects to the master database first, so we have a place to run the CREATE DATABASE command from.
  • -i 01-CreateDatabase.sql tells SQL Server which file to run.

Step 4: Connect to the Database and Create Your SQL File

  1. Click the SQL Server icon in the left sidebar, the one that looks like a cylinder, then click Add Connection.
  2. Fill in the fields: Server name localhost,1433, Database name Northwind, Authentication type SQL Login, User name sa, Password P@ssw0rd.
  3. Press Enter to save the connection. You should see Northwind appear in the SQL Server panel.
  4. In the Explorer, right click and choose New File. Name it Module7Lab.sql. You'll write all your SQL in this file.

How to run a query in this file

Type a statement, highlight it by clicking and dragging over it, right click, and choose Execute Query. Results show up in the Results panel at the bottom. You can keep every statement you write this semester in this same file, just highlight only the one you want to run each time.

Step 5: Write and Run SELECT Queries

Type each of these into Module7Lab.sql, highlighting and running each one before moving to the next.

  1. First, tell SQL Server which database to use:
    USE Northwind;
  2. Retrieving all columns with *: the * wildcard grabs every column from a table at once.
    SELECT * FROM Shippers;
  3. Sorting with ORDER BY: sorts records ascending by default, or descending if you add DESC.
    SELECT TOP 5 ContactName, Country, Phone FROM Customers ORDER BY Country, ContactName;
  4. Filtering with WHERE: narrows results down to matching rows, here every order for customer ALFKI.
    SELECT CustomerID, OrderDate, ShipCity FROM Orders WHERE CustomerID = 'ALFKI';
  5. Combining tables with JOIN: JOIN links two tables that share a relationship, here CustomerID connects Customers and Orders.
    SELECT TOP 5 c.CompanyName, o.OrderDate FROM Customers AS c JOIN Orders AS o ON c.CustomerID = o.CustomerID WHERE c.CompanyName = 'QUICK-Stop';

Background: Modifying Data

INSERT adds new rows to a table. You list the columns you're filling in, and a VALUES clause with the data for each one.

INSERT INTO Customers (CustomerID, ContactName, CompanyName, Country) VALUES ('ALICE', 'Alice Johnson', 'Wonderful Widgets', 'USA');

UPDATE modifies existing rows. The SET clause names the column to change, and WHERE limits it to the row or rows you actually mean to change.

UPDATE Customers SET ContactName = 'Maria Anders' WHERE CustomerID = 'ALFKI';

DELETE removes rows. Always include a WHERE clause, or you'll delete every row in the table.

Why DELETE can fail: a real world example

Try running this statement, which deletes an order that already exists in Northwind:

DELETE FROM Orders WHERE OrderID = 10248;

You'll get an error instead of a deleted row. That's because the Order Details table still has records pointing at OrderID 10248, a foreign key constraint. SQL Server won't let you delete an order while other rows still depend on it. You'd need to delete those Order Details rows first. This is the database protecting you from leaving orphaned data behind, not a bug.

Alternative: Completing This Lab on Your Own Windows Computer

If you'd rather work locally on a Windows laptop instead of in the cloud, here's the short version. You'll need Visual Studio Code, an internet connection, and your GitHub account.

  1. Install Git, from the Git downloads page, accepting the defaults. Confirm it worked with git --version in a terminal.
  2. Install SQL Server Express, the free edition, from the SQL Server downloads page. Choose the Basic install. Note the server name it gives you at the end, usually localhost\SQLEXPRESS.
  3. Install the SQL Server command line tools (sqlcmd) if they weren't already bundled with SQL Server Express. Check with sqlcmd -? in a terminal first.
  4. Install the mssql extension in VS Code, the same one from Step 2 above.
  5. Fork and clone the repository: fork the class SQL repository, then in a terminal run git clone https://github.com/YOUR_USERNAME/sqlserver.git and open that folder in VS Code.
  6. Build the database: run sqlcmd -S localhost\SQLEXPRESS -E -d master -i 01-CreateDatabase.sql. The -E flag uses Windows Authentication, so there's no username or password to remember.
  7. Connect in VS Code: same as Step 4 above, but with Server name localhost\SQLEXPRESS and Authentication type Windows Authentication instead of a username and password.
  8. Complete the lab: create Module7Lab.sql, run USE Northwind; first, then work through Steps 5 and 8 through 10 above exactly the same way.
  9. Commit and push: in the terminal, run git add ., then git commit -m "Module 7 Lab", then git push. If GitHub asks for a password, use a Personal Access Token instead, found under GitHub Settings, Developer Settings, Personal Access Tokens.

Common problems on your own computer

sqlcmd not recognized: close and reopen your terminal after installing. If it still fails, find where sqlcmd installed and add that folder to your system PATH.

Can't connect to the server: open Services from the Start menu, find SQL Server (SQLEXPRESS), and make sure it says Running.

On a Mac, not Windows: SQL Server Express only runs on Windows. Complete this lab in the cloud instead, or use a Remote Desktop connection to an ITEC lab computer, see Resources on the course home page.
