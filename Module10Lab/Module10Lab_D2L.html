Module 10 Lab: SQL and Razor Practice

A lighter week to cement the ADO.NET pattern from Module 9 before we move on.

Introduction

This week is all practice, no new concepts. You already know how to connect a Razor Pages app to SQL Server with ADO.NET from Module 9. This lab gives you a fully working example to study, then asks you to build a matching page yourself, from a blank file, for a different Northwind table. Repetition is how this pattern actually sticks.

Before You Start

You'll need your GitHub account and your one shared Codespace, and the same SQL Server container and Northwind database you built in Module 9. If your container has stopped, you'll start it back up in Step 1 below.

Part 1: In Class

Everything below is what we'll build together in class.

Step 1: Reopen Your Codespace and Restart SQL Server

  1. Go to GitHub's home page, sign in, click the hamburger menu, click Codespaces, and reopen your existing Codespace.
  2. Open a terminal and check whether your SQL Server container is still running: docker ps
  3. If you don't see sqlserver in the list, start it back up: docker start sqlserver. Your Northwind database is still there, Docker containers keep their data when you stop and start them, only deleting the container erases it.

Step 2: Open the Module10Lab Folder

In the Explorer, expand the Module10Lab folder, then the NorthwindPractice project folder inside it. Open a terminal and make sure you're inside that project folder before you continue.

Step 3: Read Through the Working Suppliers Page

Open appsettings.json first, and notice the connection string is already sitting there under ConnectionStrings, so you don't have to type it into every page's code.

Now open Pages/Suppliers.cshtml.cs. This page is complete and working, nothing to add. Read through it and confirm you recognize every piece from Module 9: the connection string coming from configuration, SqlConnection opening it, SqlCommand holding the SELECT statement, and SqlDataReader looping through the results with while (reader.Read()).

Then open Pages/Suppliers.cshtml and confirm the table markup matches the same @foreach pattern from Module 9's Customers page.

Step 4: Run and Test the Suppliers Page

  1. In the terminal, type dotnet run and press Enter.
  2. Open the PORTS tab, hover over the forwarded address, and click the globe icon to open your app.
  3. Click Suppliers in the nav bar and confirm you see a real table of Northwind suppliers and their countries.

Step 5: Commit and Push Your Work

  1. Click the Source Control icon, or press Ctrl+Shift+G.
  2. Type a commit message, something like Module 10 Lab reviewed Suppliers page.
  3. Click Commit, then click Sync Changes to push it up to your fork on GitHub.

Stop Your Codespace Before You Move On

This is the step people skip, and it's the one that causes the most trouble. A Codespace left running eats into your monthly free hours whether you're touching the keyboard or not, and running out mid-semester means you can't work on labs until your hours reset. Take the thirty seconds now.

  1. Click the hamburger menu in the upper left corner.
  2. Click Codespaces.
  3. Find your Codespace in the list.
  4. Click the three dots next to it.
  5. Click Stop codespace.

Submit Part 1 of Your Lab

  1. Go to your forked repository on GitHub.com.
  2. Click inside the browser address bar to highlight the full URL.
  3. Copy the URL.
  4. Paste the URL into the Part 1 submission textbox in D2L and click Submit. You're not done yet, Part 2 is required too.

Part 2: At Home

You'll build the whole Categories page yourself this time, using the exact same skills from Part 1.

The Categories nav link is already sitting in your layout, pointing at a page that doesn't exist yet. This is required, not optional, since building the whole page yourself, without a TODO comment to fill in, is what actually proves you've got this pattern down.

Step 6: Reopen Your Codespace and Restart SQL Server

Same as Step 1: reopen your Codespace, then run docker ps and docker start sqlserver if it isn't already running.

Step 7: Create Categories.cshtml.cs

In the Explorer, right click the Pages folder and choose New File. Name it Categories.cshtml.cs.

Following the exact same pattern as Suppliers.cshtml.cs, write a CategoriesModel class that takes IConfiguration in its constructor, a List of a new Category class, and an OnGet method that connects to the database using the same connection string lookup and fills the list.

Your SQL statement should be SELECT CategoryID, CategoryName, Description FROM Categories, and your Category class needs CategoryID (int), CategoryName (string), and Description (string) properties.

Step 8: Create Categories.cshtml

Right click the Pages folder again and create Categories.cshtml. Following the exact same table pattern as Suppliers.cshtml, build a table with columns for Category ID, Category Name, and Description, looping through Model.Categories.

Step 9: Run and Test

  1. In the terminal, type dotnet run and press Enter.
  2. Open the PORTS tab and click the globe icon to open your app.
  3. Click Categories in the nav bar and confirm you see a real table of Northwind categories with their descriptions.

Step 10: Commit and Push Your Work

  1. Click the Source Control icon, or press Ctrl+Shift+G.
  2. Type a commit message, something like Module 10 Lab Categories page.
  3. Click Commit, then click Sync Changes to push it up to your fork on GitHub.

Stop Your Codespace

Same reminder as Part 1, and it matters just as much here. Don't leave this running.

  1. Click the hamburger menu in the upper left corner.
  2. Click Codespaces.
  3. Find your Codespace in the list.
  4. Click the three dots next to it.
  5. Click Stop codespace.

Submit Part 2 of Your Lab

  1. Go to your forked repository on GitHub.com.
  2. Click inside the browser address bar to highlight the full URL.
  3. Copy the URL.
  4. Paste the URL into the Part 2 submission textbox in D2L and click Submit. Congratulations on finishing Module 10.
