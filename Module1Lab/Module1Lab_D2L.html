Module 1 Lab: Getting Started with GitHub and Codespaces

Welcome to your first lab. Let's get you set up with tools you'll use all semester.

Introduction

Hey there, and welcome to GitHub. This is the platform that developers everywhere use for version control and collaboration, and by the end of this lab you'll have your own account and your own project living in the cloud.

You'll set up a free GitHub account, fork a starter repository that already has folders for every lab this semester, and spin up the one Codespace you'll reuse all term. This lab has two parts. Part 1 is what we'll do together in class. Part 2 is what you'll finish up on your own at home.

The steps are broken into small, bite sized pieces on purpose. Just follow along in order and you'll be coding in the cloud before you know it.

Step 2: Fork the Class Starter Repository

Instead of starting a project from scratch, you'll fork one shared repository that already has a folder ready for every lab this semester. You'll use this same fork all term, so this is a one time setup step.

  1. Go to the class starter repository for ITEC2505.
  2. Make sure you're signed in to your own GitHub account. Check the upper right corner of the page for your profile picture.
  3. Click the button labeled Fork near the top right of the page.
  4. On the Create a new fork screen, leave the owner set to your own account.
  5. Leave the repository name as it is.
  6. Click the green Create fork button.
  7. Give GitHub a moment to copy the repository into your account. When it's done, you'll land on your own copy. Check the address bar. It'll show your username in the URL instead of mine.

Step 3: Create Your One and Only Codespace

What's a Codespace, anyway?

A Codespace is a cloud based coding environment. It runs on Microsoft's servers, so you can reach it from any computer with a web browser, any time. Codespaces uses the same editor as Visual Studio Code.

GitHub Codespaces supports lots of programming languages, including:

  • C# (.NET), which is what we'll use most this semester
  • Java
  • Python
  • JavaScript

This is the only Codespace you'll create all semester. Every lab folder lives in the same repository, so from here on you'll just reopen this same Codespace and switch which folder you're working in.

  1. Make sure you're on your own forked copy of the repository. Check the address bar. It should show your username, not mine.
  2. Click the green Code button near the top of the page.
  3. Click the Codespaces tab in the menu that appears.
  4. Click the green Create codespace on main button.
  5. Give it a few minutes to load the first time. Grab a stretch, this is a great moment to relax while the cloud does its thing.

Step 4: Open the Module 1 Lab Folder and Run the Starter Code

  1. Look at the left side of the Codespace window. This panel is called the Explorer.
  2. If you don't see a file list, click the Explorer icon on the far left toolbar. It looks like two sheets of paper.
  3. Click the folder named Module1Lab to expand it.
  4. Click the folder named HelloWorld to expand it.
  5. Click the file named Program.cs to open it in the editor.
  6. Take a look at the one line of code already there for you: Console.WriteLine("Hello, World!");
  7. Open a terminal. If you don't see a Terminal panel at the bottom of the screen, click the hamburger menu at the top left, which is three horizontal lines, then click Terminal, then click New Terminal.
  8. In the terminal, type cd Module1Lab/HelloWorld and press Enter.
  9. Type dotnet run and press Enter.
  10. Give it a moment to build and run.
  11. Confirm you see the text Hello, World! printed in the terminal. Congratulations, that's your first program running in the cloud.

Step 5: Make a Small Change and Save Your Work

  1. Click back into the Program.cs file in the editor.
  2. Click right before the semicolon at the end of the line.
  3. Add a second line under the first that prints your own first name, for example Console.WriteLine("My name is Mary.");
  4. Press Ctrl+S, or Cmd+S on a Mac, to save the file.
  5. In the terminal, type dotnet run again and press Enter to confirm both lines print.
  6. Click the Source Control icon on the left toolbar. You can also press Ctrl+Shift+G.
  7. Type a short message in the Message textbox, something like Module 1 Lab in class work.
  8. Click the Commit button.
  9. Click the Sync Changes button to push your commit up to your fork on GitHub. This step matters, since it's how your work actually gets saved online.

Step 6: Stop Your Codespace Before You Leave

Here's a habit worth building right from lab one: stop your Codespace every time you're done working, even if you're coming back later the same day. Everyone gets a limited number of free Codespace hours each month, and a Codespace left running quietly eats into that time whether you're typing or not.

  1. Make sure you already committed and pushed your work in Step 5.
  2. Go to GitHub's home page.
  3. Click the hamburger menu in the upper left corner, which is three horizontal lines.
  4. Click Codespaces in the menu.
  5. Find the Codespace you were just using in the list.
  6. Click the three dots to the right of the Codespace name.
  7. Click Stop codespace. You'll see this same step at the end of every lab this semester, so it'll become second nature soon.

Step 8: Sign Up for the GitHub Student Developer Pack

A good time to knock this out is now, while you're thinking about it. Approval can take a few days, and GitHub sometimes asks for an extra document or two to confirm you're a student, so getting your application in early saves you a headache later.

Free GitHub accounts come with limited storage and a limited number of Codespace hours each month. Once you use those up, you won't be able to create or run a Codespace until the next month starts. The Student Developer Pack removes that limit and is completely free for students, it just takes a short application.

  1. Find your Minneapolis College student ID. If you don't have one yet, reach out to the college to get one before continuing.
  2. Go to the Student Developer Pack signup page.
  3. Click Sign up for Student Developer Pack.
  4. Click Get Student Benefits.
  5. Select the radio button labeled Students.
  6. Scroll down and type the name of your school, Minneapolis College.
  7. Click Continue.
  8. If prompted, add your school email address to your GitHub profile and verify it.
  9. Take a clear picture of your student ID.
  10. Upload the picture of your student ID.
  11. Click Process my application, then keep an eye on your email over the next few days for a decision, in case GitHub asks for more proof.

Need a hand with this application? GitHub's student support page walks through it in more detail.

Step 9: Reopen Your Codespace

Now that you've handled the two steps that live on your own computer, let's hop back into the cloud to wrap things up.

  1. Go to GitHub's home page and sign in.
  2. Click the hamburger menu in the upper left corner.
  3. Click Codespaces.
  4. Click on the name of your existing Codespace to reopen it. You've got one Codespace for the whole semester, so there's no need to create a new one here.
  5. Wait for it to finish loading.

Step 10: Confirm Your Work Is Saved on GitHub

  1. In your reopened Codespace, click the Source Control icon on the left toolbar.
  2. Confirm there are no uncommitted changes listed. If there are, type a commit message, click Commit, then click Sync Changes.
  3. Go to your forked repository on GitHub.com in a browser tab.
  4. Open the Module1Lab folder, then the HelloWorld folder.
  5. Confirm you can see your updated Program.cs file with your added line of code sitting right there online.

Step 11: Stop Your Codespace

Same reminder as before, and it's worth repeating: stop your Codespace every time you finish working.

  1. Go to GitHub's home page.
  2. Click the hamburger menu in the upper left corner.
  3. Click Codespaces.
  4. Find your Codespace in the list.
  5. Click the three dots to the right of the Codespace name.
  6. Click Stop codespace.

Bonus Fun: Meet the Octocat

Octocat, GitHub's mascot, mixes together the features of an octopus and a cat. GitHub's founders were on the hunt for a fun image for their error pages, and they found a stock illustration by graphic designer Simon Oxley of a half cat, half octopus character standing in a puddle. They bought the illustration, and it stuck.

The name Octocat is a mashup of octopus and cat. It's also a little nod to Git's octopus merge, a term used in version control when you merge multiple branches together, and it captures the collaborative spirit that GitHub is built around.
