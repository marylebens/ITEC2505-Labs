Module 1 Lab: Getting Started with GitHub and Codespaces

Introduction

Welcome to the GitHub lab. In this lab you will learn the basics of GitHub, the leading platform for version control and collaboration in software development.

You will create a free GitHub account, fork a starter repository, and set up the one Codespace you will use for every lab this semester. This lab has two parts. Part 1 is done together in class. Part 2 is done on your own at home, after class.

Follow the numbered steps in order. Each step is small on purpose, so do not skip ahead.

Before You Start: Read These Warnings

  • Warning: You will make only one Codespace this semester. Do not create a new Codespace for every lab. All 12 lab folders live in the same repository, and you will open a different folder in the same Codespace for each lab.
  • Warning: Always stop your Codespace when you are done working, even if you plan to come back later the same day. A Codespace left running uses up your free monthly hours even when you are not touching the keyboard.
  • Warning: Save your work by committing and pushing before you stop your Codespace. If you stop or delete a Codespace before committing, your changes can be lost.
  • Warning: Sign up for the GitHub Student Developer Pack this week. Free GitHub accounts have limited storage and limited Codespace hours. The Student Developer Pack gives you a free professional GitHub account with more storage and more Codespace hours. Approval can take a few days, and GitHub sometimes asks for extra documents to prove you are a student, so do not wait until you are almost out of space to apply.

We will complete these steps together during class time.

  14. Find the email from GitHub with your launch code.
  15. Copy the code from the email.
  16. Switch back to the GitHub browser tab.
  17. Paste the code into the textbox on the GitHub website.
  18. On the Welcome to GitHub screen, click Just Me.
  19. Click Student.
  20. On the screen asking about features you are interested in, click Collaborative coding.
  21. Click Continue.

  23. You should now see your GitHub Dashboard. This means your account is ready.

Step 2: Fork the Class Starter Repository

Instead of building a new project from scratch, you will fork one shared repository that already has a folder for every lab in this course. You will use this same repository, and this same fork, for the whole semester.

  1. Go to the class starter repository at github.com/marylebens/ITEC2505-Labs.
  2. Make sure you are signed in to your own GitHub account. Check the upper right corner of the page for your profile picture.
  3. Click the button labeled Fork near the top right of the page.
  4. On the Create a new fork screen, leave the owner set to your own account.
  5. Leave the repository name as it is.
  6. Click the green Create fork button.
  7. Wait for GitHub to finish copying the repository into your account. You will land on your own copy of the repository when it is done. The address bar will show your username in the URL instead of mine.

Step 3: Create Your One and Only Codespace

What is a Codespace

A Codespace is a cloud based coding environment. It runs on Microsoft's servers, so you can reach it from any computer with a web browser. Codespaces uses the same editor as Visual Studio Code.

GitHub Codespaces supports many programming languages, including:

  • C# (.NET)
  • Java
  • Python
  • JavaScript
  1. Make sure you are on your own forked copy of the repository. Check the address bar. It should show your username, not mine.
  2. Click the green Code button near the top of the page.
  3. Click the Codespaces tab in the menu that appears.
  4. Click the green Create codespace on main button.
  5. Warning: This is the only Codespace you will make this semester. Do not click this button again in a future lab. In every future lab you will reopen this same Codespace instead of making a new one.
  6. Wait for the Codespace to finish loading. This can take a few minutes the first time. Be patient.

Step 4: Open the Module 1 Lab Folder and Run the Starter Code

  1. Look at the left side of the Codespace window. This is called the Explorer.
  2. If you do not see a file list, click the Explorer icon on the far left toolbar. It looks like two sheets of paper.
  3. Click the folder named Module1Lab to expand it.
  4. Click the folder named HelloWorld to expand it.
  5. Click the file named Program.cs to open it in the editor.
  6. Read the one line of code in the file: Console.WriteLine("Hello, World!");
  7. Open a terminal. If you do not see a Terminal panel at the bottom of the screen, click the hamburger menu at the top left, which is three horizontal lines, then click Terminal, then click New Terminal.
  8. In the terminal, type cd Module1Lab/HelloWorld and press Enter.
  9. Type dotnet run and press Enter.
  10. Wait for the program to build and run.
  11. Confirm you see the text Hello, World! printed in the terminal.

Step 5: Make a Small Change and Save Your Work

  1. Click back into the Program.cs file in the editor.
  2. Click right before the semicolon at the end of the line.
  3. Add a second line under the first line that prints your own first name, for example Console.WriteLine("My name is Mary.");
  4. Press Ctrl+S, or Cmd+S on a Mac, to save the file.
  5. In the terminal, type dotnet run again and press Enter to confirm both lines print.
  6. Click the Source Control icon on the left toolbar. You can also press Ctrl+Shift+G.
  7. Type a short message in the Message textbox, such as Module 1 Lab in class work.
  8. Click the Commit button.
  9. Click the Sync Changes button to push your commit up to your fork on GitHub.

Step 6: Stop Your Codespace Before You Leave

Warning: Do this every single time you finish working, in every lab, for the rest of the semester.

  1. Make sure you already committed and pushed your work in Step 5. Do not stop the Codespace before saving your work.
  2. Go to GitHub's home page.
  3. Click the hamburger menu in the upper left corner, which is three horizontal lines.
  4. Click Codespaces in the menu.
  5. Find the Codespace you were just using in the list.
  6. Click the three dots to the right of the Codespace name.
  7. Click Stop codespace.

Step 9: Sign Up for the GitHub Student Developer Pack

Warning: Do this soon. Approval can take a few days, and GitHub sometimes needs extra documents from you before it approves your account.

Free GitHub accounts have limited storage and a limited number of Codespace hours each month. Once you use them up, you will not be able to create or run a Codespace until the next month. The Student Developer Pack removes this limit and is free for students, but it requires an application and proof that you are a student.

  1. Find your Minneapolis College student ID. If you do not have one, contact the college to get one before continuing.
  2. Go to the Student Developer Pack signup page.
  3. Click Sign up for Student Developer Pack.
  4. Click Get Student Benefits.
  5. Select the radio button labeled Students.
  6. Scroll down and type the name of your school, Minneapolis College.
  7. Click Continue.
  8. If prompted, add your school email address to your GitHub profile and verify it.
  9. Take a clear picture of your student ID.
  10. Upload the picture of your student ID.
  11. Click Process my application, then wait for an email from GitHub with your decision. Check your email over the next few days in case GitHub asks for additional proof.

If you need help with this application, you can get help from GitHub Support.

Step 10: Confirm Your Work Is Saved on GitHub

  1. In your reopened Codespace, click the Source Control icon on the left toolbar.
  2. Confirm there are no uncommitted changes listed. If there are, type a commit message and click Commit, then click Sync Changes.
  3. Go to your forked repository on GitHub.com in a browser tab.
  4. Open the Module1Lab folder, then the HelloWorld folder.
  5. Confirm you can see your updated Program.cs file with your added line of code.

Step 11: Stop Your Codespace

Warning: Do not skip this step. Do this every time you finish working.

  1. Go to GitHub's home page.
  2. Click the hamburger menu in the upper left corner.
  3. Click Codespaces.
  4. Find your Codespace in the list.
  5. Click the three dots to the right of the Codespace name.

Bonus Fun: Octocat

Octocat, GitHub's mascot, combines the features of an octopus and a cat. GitHub's founders were looking for a fun image for their error pages and found a stock illustration by graphic designer Simon Oxley of a half cat, half octopus character standing in a puddle. They purchased the illustration, and it became associated with GitHub.

The name Octocat combines octopus and cat. The mascot is a nod to Git's octopus merge, a term used in version control when merging multiple branches, and it also reflects the collaborative nature of software development that GitHub is built around.
