Module 9 Lab: Creating a Web GUI with ADO.NET

Let's build a full-stack app that displays real Northwind data using ADO.NET.

Introduction

Today we'll build a web GUI that displays a list of customers from the Northwind database using ADO.NET, in a GitHub Codespace. Northwind is the same database Microsoft built for teaching SQL, based on a fictional gourmet food company.

We'll use Razor Pages again, but this time the data comes from a real SQL Server database instead of a hardcoded list, using ADO.NET, the lower-level toolkit for talking to a database directly with SQL.

Background: Steps for Building a Full-Stack App

  1. Set up the project, an ASP.NET Core Razor Pages app with a page ready to show data.
  2. SqlConnection opens the connection to the database.
  3. SqlCommand holds the SQL statement you want to run and executes it.
  4. SqlDataReader reads the rows that come back, one at a time.

Background: How ADO.NET, EF Core, and LINQ Fit Together

LINQ is query syntax built into C# itself. It works on in-memory collections, like the Pokemon list from Module 8, and it also translates into SQL when used with EF Core. It's not a database tool by itself, it's just C# syntax.

EF Core (Entity Framework Core) is an ORM, an object relational mapper. It maps C# classes to database tables and translates LINQ queries into SQL for you, using ADO.NET internally to actually talk to the database.

ADO.NET is the foundation layer. You write raw SQL yourself and manage the connection, command, and reader directly. It's more typing, but it gives you maximum control, which is exactly why we're learning it: once you understand what's happening underneath, EF Core stops feeling like magic.

Step 2: Set Up the SQL Server Container

We'll use Docker to run SQL Server in its own isolated container, right alongside your Codespace.

  1. Create the container:
    docker run -e "ACCEPT_EULA=Y" -e "SA_PASSWORD=P@ssw0rd" -p 1433:1433 --name sqlserver -d mcr.microsoft.com/mssql/server:2019-latest

    If a popup asks to open a browser on port 1433, ignore it. That's a database server starting up, not a web server.

  2. Get a root shell inside the container so we can install a couple of tools:
    docker exec -it --user root sqlserver bash
  3. Install the SQL Server command line tools, one command per line:
    apt-get update
    apt-get install -y mssql-tools unixodbc-dev

    If you hit a license acceptance error, run ACCEPT_EULA=Y apt-get install -y mssql-tools unixodbc-dev instead.

  4. Type exit to leave the container's shell and return to your Codespace terminal.

Step 3: Build the Northwind Database

  1. Create the empty database:
    docker exec -it sqlserver /opt/mssql-tools/bin/sqlcmd -S localhost -U sa -P P@ssw0rd -Q "CREATE DATABASE Northwind"
  2. Download CreateNorthwind.sql, then in the Explorer, right click in the empty space and choose Upload to bring it into your Codespace. It needs to land in the repository root, alongside README.md, not inside a subfolder, or the next command won't find it.
  3. Make sure you're in the folder containing CreateNorthwind.sql (use cd .. if you need to move up), then copy it into the container:
    docker cp CreateNorthwind.sql sqlserver:/CreateNorthwind.sql
  4. Run the script to build and populate the database. Be patient, this can take a few minutes, and the only output you'll see is "Changed database context to Northwind."
    docker exec -it sqlserver /opt/mssql-tools/bin/sqlcmd -S localhost -U sa -P P@ssw0rd -i /CreateNorthwind.sql
  5. Verify it worked:
    docker exec -it sqlserver /opt/mssql-tools/bin/sqlcmd -S localhost -U sa -P P@ssw0rd -d Northwind -Q "SELECT ProductName FROM Products"

Step 4: Understand the Customer Page Files

Open Pages/Customers.cshtml.cs. Notice the Customer class at the bottom is already written for you, it's just a data holder whose properties match the columns we're pulling from the Customers table. You won't touch that part.

You will fill in OnGet in the CustomersModel class above it, that's where the actual ADO.NET code goes.

Step 5: Write the ADO.NET Code

Replace the TODO comment inside OnGet with this code:

using System.Data.SqlClient;

string connectionString = "Server=localhost;Database=Northwind;User Id=sa;Password=P@ssw0rd;TrustServerCertificate=True;";

using (SqlConnection connection = new SqlConnection(connectionString))
{
    connection.Open();
    string sql = "SELECT CustomerID, CompanyName, ContactName, Country FROM Customers";
    using (SqlCommand command = new SqlCommand(sql, connection))
    {
        using (SqlDataReader reader = command.ExecuteReader())
        {
            while (reader.Read())
            {
                Customers.Add(new Customer
                {
                    CustomerID = reader.GetString(0),
                    CompanyName = reader.GetString(1),
                    ContactName = reader.GetString(2),
                    Country = reader.GetString(3)
                });
            }
        }
    }
}

Notice the pattern: open a connection, wrap a SQL string in a command, run the command with ExecuteReader, and loop through the reader one row at a time with while (reader.Read()). You'll reuse this exact pattern in Part 2.

Step 6: Build the Customer Table

Open Pages/Customers.cshtml and replace the placeholder paragraph with this table:

<table class="table">
    <thead><tr>
        <th>Customer ID</th>
        <th>Company Name</th>
        <th>Contact Name</th>
        <th>Country</th>
    </tr></thead>
    <tbody>
        @foreach (var customer in Model.Customers)
        {
            <tr>
                <td>@customer.CustomerID</td>
                <td>@customer.CompanyName</td>
                <td>@customer.ContactName</td>
                <td>@customer.Country</td>
            </tr>
        }
    </tbody>
</table>

Step 10: Create Products.cshtml.cs

In the Explorer, right click the Pages folder and choose New File. Name it Products.cshtml.cs.

Following the exact same pattern as Customers.cshtml.cs from Steps 4 and 5, write a ProductsModel class with a List of a new Product class, an OnGet method that connects to the database and fills that list, and the Product class itself with properties for ProductID, ProductName, and UnitPrice.

Your SQL statement should be SELECT ProductID, ProductName, UnitPrice FROM Products. ProductID and UnitPrice are numbers, so read them with reader.GetInt32(0) and reader.GetDecimal(2) instead of GetString.
