Module 11 Lab: CRUD Operations in the Rubber Duck Store

Let's give programmers a store for their debugging companions, and give ourselves practice with all four CRUD operations.

Introduction

Today we'll build a small web app that displays rubber ducks for sale, made for programmers to use while debugging. Along the way you'll practice CRUD: Create, Read, Update, and Delete, the four basic operations every database-backed app needs. We'll set up the database and the Read operation together, then you'll add Create, Update, and Delete yourself in Part 2.

Background: What Is CRUD?

CRUD stands for the four things almost every app needs to do to its data:

  • Create: add a new row, with an INSERT statement.
  • Read: look up existing rows, with a SELECT statement. We already practiced this in Modules 7, 9, and 10.
  • Update: change an existing row, with an UPDATE statement.
  • Delete: remove a row, with a DELETE statement.

  1. Open create_ducks_table.sql and take a look. It creates a Ducks table and inserts two sample ducks. Leave it as is.

Then open Pages/RubberDucks.cshtml and confirm you can trace how the dropdown, the form, and the @if (Model.SelectedDuck != null) block work together to show the picked duck's details.

Part 2: At Home

You'll add Create, Update, and Delete yourself this time, using the exact same skills from Part 1.

In Part 1 you studied a working Read operation. Now you'll write the other three CRUD operations yourself, each one following the exact same connection, command, and execute pattern, just with a different SQL statement. This is required, not optional, since the whole point of this module is proving you can do all four.

Step 7: Reopen Your Codespace

Go to GitHub's home page, sign in, and reopen your existing Codespace, same as Step 1.

Step 8: Write the Create Operation

Open Pages/RubberDucks.cshtml.cs. Replace the first TODO comment with a method:

public IActionResult OnPostAdd(string name, string description, decimal price, string imageFileName)

Inside it, following the exact same connection-and-command pattern as LoadDuckList, open a SqliteConnection, create a command whose CommandText is an INSERT statement, add parameters for @Name, @Description, @Price, and @ImageFileName using command.Parameters.AddWithValue for each, then call command.ExecuteNonQuery() instead of ExecuteReader, since INSERT doesn't return rows. Call LoadDuckList() and return Page() at the end, same as OnPost does.

Then open Pages/RubberDucks.cshtml and replace the matching TODO comment with a form: text inputs for name, description, and imageFileName, a number input for price, and a submit button with asp-page-handler="Add" so it calls OnPostAdd.

Why parameters instead of building the SQL string by hand: AddWithValue keeps user-entered text from being interpreted as part of the SQL command itself. Typing the values directly into the SQL string is a security risk called SQL injection, and parameters are how you avoid it.

Step 9: Write the Update Operation

Replace the second TODO comment in RubberDucks.cshtml.cs with a method:

public IActionResult OnPostUpdatePrice(int duckId, decimal newPrice)

Inside it, open a connection, create a command whose CommandText is an UPDATE statement that sets Price to @NewPrice where Id equals @DuckId, add both parameters, call ExecuteNonQuery, then LoadDuckList() and return Page().

In RubberDucks.cshtml, replace the matching TODO comment with a form: a dropdown for duckId using asp-items="Model.DuckList", a number input for newPrice, and a submit button with asp-page-handler="UpdatePrice".

Step 10: Write the Delete Operation

Replace the third TODO comment in RubberDucks.cshtml.cs with a method:

public IActionResult OnPostDelete(int duckId)

Inside it, open a connection, create a command whose CommandText is a DELETE statement that removes the row where Id equals @DuckId, add that parameter, call ExecuteNonQuery, then LoadDuckList() and return Page().

In RubberDucks.cshtml, replace the last TODO comment with a form: a dropdown for duckId, and a submit button with asp-page-handler="Delete".

Step 11: Run and Test All Four Operations

  1. In the terminal, type dotnet run and press Enter, then open your app from the PORTS tab.
  2. Create: add a new duck of your own design. Use one of the two existing image filenames for now, since you haven't uploaded a third image. Confirm it shows up in the dropdown afterward.
  3. Update: pick a duck and change its price. Use Read to confirm the new price stuck.
  4. Delete: pick a duck and delete it. Confirm it's gone from the dropdown afterward.
  5. When you're done testing, go back to the terminal and press Ctrl+C to stop the server.
